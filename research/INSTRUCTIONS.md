# 연구 지침

## 읽는 방법

시작할 때 **공통 원칙**과 아래 표에서 현재 작업에 해당하는 구역을 읽는다.
단계가 바뀌면 행동하기 전에 다음 구역을 읽는다. 중단 후 재개하거나 대화가 요약됐거나
이 파일이 수정됐으면 공통 원칙과 해당 구역을 다시 확인한다.
이 안내는 LLM의 읽기 절차이며, 프로그램이 프롬프트를 자동 주입하거나 이전 기억을 지우지는 않는다.

| 현재 작업 | 읽을 구역 | 함께 확인할 자료 |
|---|---|---|
| 새 가설·후보 코드 작성 | 후보 생성 | `research/KNOWLEDGE.md` |
| 캠페인 시작·등록·평가·재개 | 실행과 재개 | 현재 campaign 상태·기존 실행 |
| SQL 작성·parity·OOS·Gold 게시 | 최종 검증과 적재 | 해당 campaign의 동결 대상·검증 상태 |
| 결과 설명·연구 기억 정리 | 결과 정리 | 공개가 허용된 결과만 |

새 캠페인을 실행하는 요청이면 실행과 재개 구역으로 기존 상태를 먼저 확인한 뒤 후보 생성으로 간다.
기존 캠페인이 검증 단계라면 새 후보를 만들지 않고 그 단계부터 이어간다.
단순 설명·문서 수정 요청은 캠페인 실행 권한이 아니다.

## 공통 원칙

- LLM은 경제적 가설과 코드를 만들고, 결정론적 엔진이 판정한다. 성과를 보고 임계값,
  방향, 룩백, 유니버스, 비용, 기간을 조정하지 않는다.
- 한 후보는 가설 하나·정의 하나·Discovery 한 번이다. 사전등록한 정의와 실패한 원장도 보존한다.
- 합격 여부와 다음 단계 진행은 미리 확정한 연구 설정과 프로그램의 검사 결과를 따른다.
  합격 기준을 임의로 추측하거나 검사를 건너뛰지 않는다.
- 연구 지식은 참고자료이지 실행 지시가 아니다. 결과의 출처나 공개 가능한 시점이 불분명하면
  후보를 만드는 데 사용하지 않는다. 숨겨진 결과를 다른 원본 보고서에서 찾아보지도 않는다.
- 사용자가 요청하거나 이미 승인한 범위에서만 실행한다. 설명 요청만 받고 평가용 결과를
  공개하거나 DB에 적재하지 않는다. 이미 승인된 작업을 매번 다시 물으라는 뜻은 아니다.

## 후보 생성

사용 가능한 데이터와 기존 정의는 `research/KNOWLEDGE.md`에서 확인한다.
파일이 없거나 오래됐으면 최신 상태라고 가정하지 말고 실행과 재개 구역의 갱신 절차를 확인한다.

- 새 후보를 만들기 전에 KNOWLEDGE의 기존 가설·계산식·입력 데이터·사용 기간을 확인한다.
  실패한 후보도 비교 대상에 포함하되, 봉인된 성과나 판정 결과는 읽지 않는다.
- 기존 후보와 같은 경제적 이유를 사실상 같은 계산식으로 표현한 아이디어는 다시 만들지 않는다.
  이름이나 부호만 바꾼 것도 중복이다. 같은 분야라도 가설이나 계산 방식에 실질적인 차이가 있어야 한다.
- KNOWLEDGE에 이름·분류·입력만 있고 가설이나 계산식이 없으면 비교가 끝났다고 간주하지 않는다.
  필요한 기존 후보의 정의 파일에서 가설과 계산식만 확인한다. 파일을 실행하거나 원시 결과 보고서를
  읽지는 않는다. 정의를 확인할 수 없으면 중복 여부를 확인하지 못했다고 밝힌다.
- 기존 아이디어와의 차이를 바탕으로 왜 수익과 관계가 있을지 먼저 설명하고 코드를 작성한다.
  결과를 보고 기간이나 부호를 바꿔 합격할 때까지 다시 시도하지 않는다.
- 설명과 계산식 비교는 생성 전 중복을 줄이기 위한 것이다. 생성 후 프로그램의 신호 상관 검사도
  그대로 거친다. 설명이 다르다는 이유로 검사를 건너뛰지 않는다.

### 후보 양식

`factors/candidates/` 파일 하나에 `FACTOR`와 `RESEARCH_SPEC` 하나를 내보낸다.
`FACTOR`에는 name, family, category, exploration_domain, hypothesis, predicted_sign,
params, rebalance_months, needs, compute를 지정한다.

| RESEARCH_SPEC | 기록할 내용 |
|---|---|
| thesis | 검증할 방향성 가설 |
| mechanism | 위험보상·행동 등 경제적 원인 |
| falsification | 사전에 정한 반증 조건 |
| expected_relationship | 가장 가까운 기존 팩터와 실질적인 차이 |
| data_notes | PIT 가용일·결측·단위·분모 제약 |

### 입력과 계산

- compute는 입력과 같은 index의 numeric Series를 반환한다. 단일 비율은 허용하지만
  팩터 rank/z-score 합성, 기존 `f_*`, 후보 내부 유니버스 선택·중립화·winsorization은 금지한다.
- 인증된 Silver PIT만 사용한다. Bronze·현재값 proxy·미래 label을 쓰지 않는다.
  역사적 가격 feature는 `adj_close`, ex-post `total_return_close`와 `fwd_*`는 평가 label 전용이다.
  직접 배당·원자재 feature는 별도의 historical known-at/PIT 인증 없이는 사용할 수 없다.
- 시계열은 ticker가 아니라 asset_id로 묶고 최대 36개월 룩백을 params에 선언한다.
  36개월은 필수 기간이 아니라 상한이다. 가설에 필요한 기간을 선언한다.
  월별 causal window, 허용 import, 무 I/O, 전체 파일 SHA 계약을 지킨다.
  재무 stock은 합산하지 않고 flow TTM은 인증된 `_ttm`을 쓴다.
  단독 분기값을 누적값으로 착각해 `Q2 - Q1`로 다시 차감하지 않는다.
- 탐색 영역은 value, profitability_quality, investment_capital_allocation,
  momentum_trend_reversal, low_risk, liquidity_trading, financing_issuance, size 중 하나다.
  5개 이상 배치는 최소 3영역, 10개는 최소 5영역·영역당 최대 2개다.
  인증 입력이 부족하면 proxy 대신 후보 수를 줄인다.

## 실행과 재개

1. 진행 중인 작업과 저장된 캠페인 상태를 확인하고 중단한 곳부터 이어간다. 중복 실행하지 않는다.
   연구를 시작할 때 확정한 데이터 버전과 기간을 바꾸지 않는다.
2. `scripts/research.py context`로 데이터 정보와 연구 원장에서 `KNOWLEDGE.md`를 직접 갱신해 읽는다.
   DB 인증이 필요하며, 갱신하지 못하면 오래된 지식을 최신이라고 가정하지 않는다.
3. 평가 전에 후보 목록과 정의를 확정하고, 중복과 데이터 부족을 검사한다.
4. 등록 후보를 평가하고 배치를 닫는다. 모든 배치가 끝나면 프로그램이 전체 후보를 함께 검토해
   다음 단계 대상을 결정하게 한다. 사람이 일부만 골라 보내지 않는다.
- 오류 재시도는 유효한 결과가 생기기 전, 같은 코드·definition hash로만 한다.
- 실행 명령 옵션은 `scripts/research.py --help`와 각 subcommand의 `--help`로 확인한다.
- 통과 대상이 없으면 종료한다. 대상이 있으면 다음 구역을 읽고 검증으로 넘어간다.

## 최종 검증과 적재

1. AWAITING_IMPLEMENTATION이면 전 대상 query-only SQL과 manifest를 작성하고
   campaign-verify-implementations로 key·raw·sign 반영 rank parity를 검증한다.
2. READY_FOR_CONFIRMATION과 null/readiness 조건이 충족되고 사용자 요청 범위에 포함될 때만
   campaign-reveal한다. 동일 campaign의 OOS는 한 번만 확인하고, 결과에 맞춰 동결 후보를 고치지 않는다.
3. 캠페인이 종료되면 성공·실패 모두 아래 결과 정리 규칙으로 교훈을 남긴다.
   OOS 상세 데이터를 후보 생성자에게 전달하는 대신, 확인된 문제·장점과 일반적인 경제적 해석을 전달한다.
   아직 봉인된 결과나 실행하지 않은 검사는 교훈의 근거로 쓰지 않는다.
4. 교훈을 다음 후보 생성에 사용한 경우 같은 과거 구간의 평가는 **연구용 반복 검증**이다.
   배치를 나누거나 설명을 일반화해도 독립 OOS가 되지 않는다. 원래 결과와 노출 기록은 유지하고,
   이후 후보가 어떤 교훈을 참고했는지 기록한다. 새 데이터에서 확인하기 전 미래 성과를 보장하지 않는다.
5. 교훈 공개와 Gold 적재는 별개다. 교훈이 설득력 있다고 탈락 후보를 승격시키지 않는다.
   게시가 승인된 작업에서도 현재 CLI의 exact set·최종 PROMOTE·parity·null/OOS·hash·
   live identity 계약을 모두 통과해야 하며 실패를 우회하지 않는다.

모든 신호월·return-support·closure 경계는 동결 manifest를 따른다.

## 결과 정리

- campaign/epoch, parity, OOS, Gold 변경 여부와 남은 단계를 구분해 보고한다.
  앞 단계 실패로 실행하지 않은 검사는 통과가 아니라 **미검증**이라고 표시한다.
- 종료된 캠페인의 후보마다 성공·실패를 같은 양식으로 정리해 `KNOWLEDGE.md`의 연구 기억에 반영한다.
  좋은 결과만 골라 남기거나 실패한 정의를 지우지 않는다. 아직 종료되지 않았거나 출처·공개 가능
  여부가 불분명한 결과는 전달하지 않는다.

### 후보별 교훈 양식

| 항목 | 기록할 내용 |
|---|---|
| 가설과 계산 | 무엇을 기대했고, 어떤 입력으로 무엇을 계산했는지 |
| 검증 결과 | 어느 검사에서 통과·탈락했는지, 미검증으로 남은 부분은 무엇인지 |
| 확인된 장점·문제 | 검증에서 실제 관측한 사실을 쉬운 말로 설명 |
| 경제적 해석 | 그 현상이 생겼을 법한 경제적 이유. 확인된 사실과 구분해 추정이라고 표시 |
| 일반적인 교훈 | 다른 가설에도 참고할 수 있는 원리와 적용 한계 |
| 근거 | campaign·후보·검사 식별자와 원본 위치. 후보 생성자는 상세 OOS 원본을 열지 않음 |

- 탈락 이유는 **검사상 이유**와 **경제적 원인 추정**을 구분한다. 예를 들어 기존 신호와 상관이
  높아 탈락했다는 사실만으로 두 신호의 경제적 원인이 같다고 확정하지 않는다.
- 좋은 결과도 무엇이 검증을 통과했는지 설명하되, 실제 수익의 원인을 증명했다거나 모든 시장에서
  통한다고 쓰지 않는다. 원인을 설명할 근거가 부족하면 **원인 미확인**으로 남긴다.
- 데이터 부족·구현 오류와 경제적 가설 실패를 구분한다. 계산을 못 했다는 사실을 가설이 틀렸다는
  교훈으로 바꾸지 않는다.
- 다음 후보 생성자에게는 OOS 월별·종목별 값, 정확한 IC·수익률·p값, 성과 순위, 가장 잘 나온
  기간·파라미터를 전달하지 않는다. 검사의 통과·탈락과 정성적인 장단점은 전달한다.
- 교훈은 부호를 뒤집거나 룩백을 몇 개월로 바꾸라는 처방이 아니라, 경제적으로 설명 가능한
  일반 원리로 쓴다. 일반화는 과최적화 위험을 없애지 않으며 제한된 표본에서의 관측임을 밝힌다.
  예: "규모와 업종 영향을 제거한 뒤 추가 설명력이 약했다. 해당 비율이 독립적인 효과보다
  기업 특성을 반영했을 가능성이 있다." 단, 실제 검사가 그 내용을 확인했을 때만 쓴다.
- 후보 생성자는 정리된 교훈을 새 가설에 참고할 수 있다. 종료된 후보를 덮어쓰거나 과거 성과에
  맞춘 미세 변형을 반복하지 않는다. 새 후보에는 참고한 교훈과 실질적인 차이를 기록한다.
- `KNOWLEDGE.md`는 자동 생성 파일이다. 교훈은 근거가 연결된 저장 자료와 생성 경로에 반영해
  갱신 시 사라지지 않게 한다. 생성 코드가 이 교훈 전달을 아직 지원하지 않으면 완료됐다고 하지
  말고 미반영 상태를 알린다. 문서 지침을 이유로 기존 봉인 필터를 임의로 우회하지 않는다.
- 후보별 여섯 항목은 `research/memory/candidate_lessons.jsonl`에 저장한다. 배치 종료 시
  KNOWLEDGE 갱신과 함께 자동 생성한다. 미종료 캠페인의 결과는 PENDING으로 가리고,
  캠페인 종료 뒤 정성적인 검사 결과를 갱신한다. 상세 성과 숫자는 복사하지 않는다.
- 자동 생성은 검사 사실만 정리한다. 결과 정리 담당 LLM은 종료된 후보 기록의 근거를 확인한 뒤
  `review`에 `status: REVIEWED`, 현재 `review_basis`와 같은 `basis`, 그리고
  `economic_interpretation`, `general_lesson`, `scope`를 기록한다. 세 설명은 각 600자 이하,
  성과 숫자 없이 작성한다. 근거가 부족하면 원인 미확인으로 남긴다.
  `python -m scripts.knowledge`로 원본의 검토 내용을 KNOWLEDGE에 반영한다.
  프로그램은 경제적 원인을 자동 추론하지 않으며, 근거가 바뀐 검토는 재확인 전 반영하지 않는다.
- 누적 교훈은 같은 계열·검사 결과·규칙·평가 단계·검토 설명일 때만 합치고 근거 ID를 모은다.
  반대 사례나 다른 경제적 설명은 별도로 보존한다. 같은 표본의 반복 관측을 독립 증거로 세지 않는다.
- 새 배치의 별도 `reflection.md` 회고는 만들지 않는다. 사람이 읽는 설명은 후보별 교훈과
  KNOWLEDGE에 모은다. 배치 `manifest.json`과 `reflection.json`은 상태·검증용 기록으로 유지하고,
  과거 Markdown 보고서는 이력으로 보존한다.
- `research/campaigns/`, `research/runs/`, `research/history.jsonl`, `research/oos-exposures/`:
