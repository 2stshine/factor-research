# TeamAlpha Research Observatory

Public, read-only research dashboard (public access explicitly authorized by the owner). Static HTML/CSS/JS; no database credentials or raw stock panel in the browser.

## Data boundaries

- `research-catalog.json`: only released, authenticated lesson evidence. Pending records appear as counts only.
- `gold-catalog.json`: actual source freshness is retained. A historical approved comparison set is not a live approval query.
- PROMOTE is a research verdict, not proof of Gold publication.
- OOS Rank IC is distinct from Discovery portfolio gross/cost/net. Missing values remain missing.
- Regime input assumptions, insufficient states, UNKNOWN, confidence intervals, and monthly alignment are retained.
- The default regime view is the four coarse market states. Four axes and sixteen combinations remain secondary diagnostics; no classifier thresholds or frozen research results are changed by display order.
- The current input-readiness panel is source-only, separate from frozen historical factor performance. Historical coverage is not current readiness. The production/inflation direction proxy is not retrofitted to old factor studies.
- Reviewed lessons include an independent critic bound to each analysis and evidence hash. Review completion is not causal proof; unavailable historical diagnostics stay unavailable.
- Research-result interpretation audience only; not a candidate-generation OOS feedback feed.
- Approved factors default to earliest discovery first; recent-first and English-ID name sorting are also available. Discovery means the earliest retained research epoch registration bound to the catalog definition, not approval, idea creation, or backtest dates. Equal timestamps use the research cycle sequence. Unknown dates stay last in either chronological direction.
- `discovery-order.json` is generated by `scripts/dashboard_exports/export_discovery_order.py` in the parent repository and validated/joined during snapshot packaging. Each factor retains the timestamp, definition binding, and source references in the downloadable Gold JSON. The current snapshot has 35 linked dates and 14 unknown dates (including one historical definition mismatch).

## Refresh

Run the authenticated read-only exporters from the factor-research repository, then:

```sh
node scripts/sync-snapshot.mjs /absolute/path/to/research-dashboard-source
node scripts/check-site.mjs
python3 -m http.server 4173 --bind 127.0.0.1 --directory dist
```

Exporters are maintained at the repository's `scripts/dashboard_exports/` (also originally generated in `output/research-dashboard-source/`). No scheduled/live refresh is implied. Updating source and publishing are separate steps. Preserve the existing `.openai/hosting.json` project identity and the owner's explicitly authorized public Vercel audience.

The portable app snapshot is versioned as ordinary files under `apps/research-observatory/` in the factor-research repository, not as an unresolvable Git submodule. This machine also retains the original Sites-managed local checkout metadata; its `.git/` directory and `.vercel/` credentials/settings are not part of the portable snapshot. Deploy only the sanitized static bundle, never the parent research directory. Do not ship `.env`, AWS/RDS credentials, stock-level panels, or withheld OOS artifacts.

The dashboard is reading/navigation only; it has no state-mutating tools, approval buttons, or data-write endpoints.

## Optional Vercel deployment

`vercel.json` serves the sanitized `dist/` directory without a build; `.vercelignore` excludes research source, scripts, and credentials. This configuration alone does not create a Vercel project, deploy it, or enable authentication.

The owner confirmed personal non-commercial Hobby eligibility and explicitly enabled public access for the existing `teamalpha-research-observatory` project. Preserve that audience; do not use the CLI `--public` source-exposure option. Publish only the sanitized `dist/` allowlist, then verify the deployment and intended anonymous page/data access. For any new project, default to protected/private until separately authorized. Never upgrade to a paid plan automatically. Git auto-deployment is separate from CLI deployment and has not been configured.
