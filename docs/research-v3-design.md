# 레퍼런스 팩터 기반 연구 v3

작성: 2026-10-02 · 새 세대: `reference-factor-v3`

## 방향

이제 목표는 **서로 다른 단일 팩터를 많이 승인하는 것**이 아니라, 검증 가능한
기준 팩터를 쌓고 그 위에서 추가 정보를 연구하여 비용을 고려한 월별 전략을 만드는 것이다.
문헌에서 유명하다는 사실, 국내에서 재현됐다는 사실, 매매에 도움이 된다는 사실은 다르다.

```text
인증된 데이터 / 시점·공시·상폐·체결 계약
                    │
        새 레퍼런스 라이브러리 (문헌 → 국내 재구현)
                    │
       단일 팩터 가설 → 기존 검증·적응형 진단·독립 교훈 검토
                    │                 ↑
       기준 팩터 대비 추가 정보 ────────┘
                    │
       학습 기간 안에서 선택 / 압축 / 릿지 적합
                    │
       다음 달 종목 수익률 예측 → 제약·비용을 적용한 비중
                    │
       월초 실행 / 외부 검증 / 별도 전략 승인
```

릿지의 초기 타깃은 종목별 다음 월 수익률로 둔다. 팩터 포트폴리오 간 자금 배분은
다른 타깃·위험 추정·실행 계약이 필요한 별도 전략이며 자동으로 섞지 않는다.
이 문서의 초기값은 운영 제안이지 문헌이 입증한 한국 시장 최적값이 아니다.

## 레거시 보존과 새 출발

- 기존 코드·캠페인·실패·교훈·OOS 노출 원장을 삭제하거나 기존 결과를 수정하지 않는다.
  변경 전 working-tree 파일을 내용 해시 기반 보관본으로 남긴다. Git 커밋 전 수정도 포함한다.
- 기존 `gold.factor` / `gold.factor_value`는 **레거시 원본으로 원위치 보존**한다.
  새 세대의 입력 목록은 빈 목록부터 시작하고, `status=APPROVED` 전체를 자동 조회하지 않는다.
  메타데이터 목록 보관은 수천만 개 값 행을 별도 DB로 복제했다는 뜻이 아니다.
- 새 라이브러리의 `generation_id + factor_id + definition_sha256 + 승인 근거`를 정확히
  맞춘 입력만 사용한다. 옛 팩터 이름에 v3 태그만 붙이거나 기존 점수를 가져오지 않는다.
- 새 정의의 구현은 기존 계산 코드를 검토해 참고할 수 있지만 새 자료·새 계약에서 다시 검증한다.
  이전 팩터에 이미 노출된 과거 기간은 계속 **재사용 역사 검증**이다. 세대 변경은 OOS 초기화가 아니다.
- 기존 실증 기억은 자동 승계하지 않는다. 검증·교훈 **절차**를 재사용하고, 측정 오류에 관한
  일반적 절차 교훈은 출처·범위 검토 후 명시적으로 이전한다.
- 데이터 복구는 연구 세대와 별개다. 이미 받은 원문은 보존하되 미완료·미인증 자료를
  새로운 Silver 입력이나 레퍼런스 팩터로 자동 승인하지 않는다.
- 로컬 차단은 DB의 모든 외부 클라이언트를 막는 권한 변경이 아니다. 운영 Gold의 물리적
  스키마 분리·읽기 전용 권한·새 발행기는 별도 마이그레이션 검증 후 진행한다.

## 팩터의 세 가지 의미

| 대상 | 예 | 사용할 곳 |
|---|---|---|
| 종목 특성값 | B/M, 영업수익성, 12–2 모멘텀 | 종목별 점수·수익률 예측 입력 |
| 팩터 포트폴리오 수익률 | 가치주−성장주, 시장 TR−무위험수익 | 위험 노출·기존 설명의 포괄 여부 진단 |
| 잠재 요인 | 수익률 행렬에서 추출한 공통 요인 | 시장 공변동·리스크 설명 |

특성값 PCA를 했다고 시장수익률 요인을 추정한 것은 아니다. 장단기 포트폴리오가 학술
진단에 유용해도 한국에서 그 숏을 실제로 체결할 수 있다는 뜻은 아니다.
시장 TR은 모든 종목에 같은 값으로 반복 입력한다고 횡단면 선별력이 생기지 않는다.

## 1. 데이터부터 정리

각 입력에는 원천·버전·단위·법인/종목 식별·통계 기준일·발표/가용일·수정 정책·커버리지를 둔다.
신호 입력과 사후 실현수익 label을 물리적 또는 엄격한 API 경계로 구분한다.
PIT 가정을 수용한 매크로는 `PIT_ASSUMED`를 유지하고, 주식 재무 데이터 인증으로 확대하지 않는다.

가용 정보가 월말 장 마감에 확정되면 다음 달 **첫 실제 거래 세션**부터 실행 가능하다.
달력 1일이나 월말 종가 체결로 대체하지 않는다. 시가·거래정지·가격제한·상폐·corporate action과
배당 반영이 확인돼야 실행형 label을 만들 수 있다. 불가하면 월말 수익 진단으로 명확히 표시한다.
현재 overlay 원장 동일성 결함 등 미해결 사항은 [전환 상태](research-v3-transition.md)에 남긴다.

## 2. 레퍼런스 라이브러리

[초기 문헌 카탈로그](research-v3-reference-library.md)를 기준으로 원형과 국내 변형을 따로 등록한다.
자료가 준비된 항목부터 **정의 동결 → 입력 검사 → 단위/시점 테스트 → Python/SQL 대사**를 한다.
문헌 항목이 카탈로그에 등록된 것만으로 사용할 수는 없다.

레퍼런스는 비교를 위한 자다. 예를 들어 규모 노출은 단독 알파가 약해도 통제 변수로
유용할 수 있다. 따라서 “통제용 재현 가능”과 “독립 알파 승인”을 별도 판정한다.
검증 실패를 승인으로 바꾸는 예외가 아니라, 서로 다른 사용 목적의 계약이다.

신규 연구의 비교 집합은 trial 시작 전에 라이브러리 버전으로 동결한다. 나중에 더 좋은
레퍼런스를 발견해 같은 trial의 비교 대상을 몰래 바꾸지 않는다.

## 3. 기존 검증·교훈 구조 재사용

유지: 단일 가설, 경제적 연결·경쟁 설명, 입력 품질 검사, 사전등록, 시행 원장,
Discovery/OOS 경계, 실제 검사 선택, 관찰/해석/미확인 구분, 독립 비평, 출처 있는 교훈.
레짐은 우선 설명·안정성 진단이다. 결과를 본 뒤 유리한 국면만 매매하는 규칙으로 바꾸지 않는다.

변경: 레거시 Gold와 상관이 높으면 무조건 탈락하는 단일 기준을 새 라이브러리에 복사하지 않는다.
새 연구에서는 같은 정보를 더 안정적·저비용·높은 커버리지로 측정하는 팩터도 연구 가치가 있다.
기존 T0–T4 등의 수치·표본 진단은 재사용 가능한 엔진이지만, 새 용도별 판정 계약을 먼저
버전 고정해야 한다. 기존 campaign gate를 소급 완화하지 않는다.

추가로 물을 질문:

1. 알려진 시장·규모·업종·가치·수익성 효과로 설명되는가?
2. 레퍼런스만 쓸 때와 새 후보를 더할 때 예측 오차·IC·비용 후 수익이 어떻게 달라지는가?
3. 차이는 특정 달·소형주·저유동성·결측·회계 기준 혼합 때문인가?
4. 새 정보가 없더라도 측정 안정성·실행비용 면에서 대체할 이유가 있는가?

독립 교훈은 이 질문에 대한 **실제로 수행한** 증거에서만 쓴다. 상관·증분 성과는 인과 증명이 아니다.
선택된 변수에 일반 회귀 p-value를 붙여 새 팩터의 진실을 선언하지 않는다.

## 4. 차원 축소·선택: 설명과 예측을 분리

두 가지 장부를 유지한다.

- **설명 장부:** 공변동 설명력, 잔차 위험, 고정 test asset의 평균수익 pricing error,
  레퍼런스 대비 추가 정보. 시장 지수 하나에 대한 R²만으로 시장 전체를 설명했다고 하지 않는다.
- **예측·전략 장부:** 다음 월 오차, 월별 IC, 거래비용 후 수익, turnover, 손실·노출·용량.

초기 비교는 작게 고정한다: (A) 새 레퍼런스 전체 + 릿지, (B) 같은 입력의 train-fit PCA + 릿지.
상관 군집 대표 선택이나 레퍼런스+신규 후보 추가 비교는 별도 사전등록 실험으로 추가한다.
처음부터 큰 조합 탐색을 돌리지 않는다. 릿지는 계수를 축소하지만 일반적으로 계수를 정확히 0으로
만드는 변수 선택기는 아니다. PCA 차원 선택과 팩터 자체 선택을 같은 이름으로 부르지 않는다.

PCA를 필수로 하지 않는 이유는 변동성이 작은 방향에도 예측 정보가 있을 수 있기 때문이다.
RP-PCA와 supervised factor selection은 확장 후보이며, 아래 baseline은 그 논문의 구현이 아니다.
상관·PCA·결측 대체·표준화·후보 선택을 **전체 기간에서 미리 수행하지 않는다**.

## 5. 시간 분할과 릿지

```text
과거 학습 ─ 내부 시간순 검증(차원·λ 선택) ─ 외부 월 예측
          다음 월: 과거 자료만 늘려 동일 절차 반복
          최종 봉인 구간: 사람의 재튜닝 없이 동결 파이프라인 평가
```

- 같은 달 종목들은 같은 fold에 둔다. 무작위 행 분할·기본 LOOCV를 사용하지 않는다.
- outer 예측 시점 전에 **실제로 label이 확정된 행**만 학습한다. 내부 검증도 동일하다.
  월말→다음 월말 label의 달력 표지만 보지 않고 실행 수익 종료·상폐 확인시각까지 반영한다.
- 실험 계약은 학습창, 내/외부 기간, hyperparameter 격자, 평가 기준, 총 비교 횟수를 동결한다.
  기간 숫자는 실제 준비된 데이터와 표본 수를 먼저 본 뒤 정한다. 구형 3년 룩백/36개월 OOS를
  새 전략의 모든 입력·학습창에 일괄 복사하지 않는다.
- 외부 월 결과는 그 월 학습에는 사용하지 않는다. 나중 월에 당시 확정된 label을 쓰는 것은
  사전 선언한 온라인 재학습 절차다. 사람이 outer 성과를 보고 설계를 바꾸면 새 실험으로 기록한다.
- 라이브러리 구축에 사용한 결과 기간 역시 전략 개발의 일부다. 오늘 승인한 팩터를 과거에
  이미 선별해 둔 것처럼 취급하지 않는다. 실제 사전 동결 이후 미래 자료가 전향 검증이다.
- 릿지 타깃의 단위, 부호, 절편, 월 가중치, 정규화·결측 정책을 명시한다.
  신호 부호를 두 번 곱하지 않는다. 학습 loss 개선이 거래 수익 개선을 보장하지 않는다.

## 6. 예측과 실제 비중은 별도

릿지 출력은 예상 수익률이다. 초기 구현은 고정 top-20% 동일가중을 비교 기준선으로 두고,
top-10%/제약 최적화 등은 별도 전략 실험으로 관리한다. 전략 최적화에는 위험 추정,
종목·업종 한도, 회전·세금·수수료·시장충격, AUM 대비 거래 참여율, 실행 불가 시 규칙이 필요하다.
이 값들이 없으면 최적 비중·실거래 가능이라고 보고하지 않는다.

KOSPI/KOSDAQ 대상과 맞는 시장 TR, 동일 모집단 동일가중, 레퍼런스-only를 병기한다.
KOSPI만 빼거나 동일가중만 빼서 모든 의미의 초과수익으로 부르지 않는다.

## 근거와 적용 범위

- [Gu, Kelly & Xiu (2020), Empirical Asset Pricing via Machine Learning](https://dachxiu.chicagobooth.edu/download/ML.pdf):
  §1.3의 시간순 train/validation/test 분리와 정규화 모형 비교를 참고했다.
  본 연구의 월별 purge·가용시각·한국 실행 제약은 우리 데이터 계약에 맞춘 추가 설계다.
- [Feng, Giglio & Xiu (2020), Taming the Factor Zoo](https://stefanogiglio.org/papers/feng-giglio-xiu-jf-2020.pdf):
  기존 팩터 대비 새 기여를 묻고 선택 오류를 고려한다는 근거다. 단순 상관 제거·릿지가
  해당 논문의 double-selection 추론을 구현했다고 주장하지 않는다.
- [Lettau & Pelger (2020), Factors that Fit the Time Series and Cross-Section](https://www.nber.org/papers/w24858):
  수익률 공변동과 평균수익 설명을 함께 다루는 확장 근거다. 특성 PCA baseline과 구별한다.
- [Chen & Zimmermann, Open Source Cross-Sectional Asset Pricing](https://www.federalreserve.gov/econres/feds/open-source-cross-sectional-asset-pricing.htm):
  정의·코드·재현 근거를 함께 보관하는 레퍼런스 라이브러리의 참고 자료다. 미국 재현을 한국 승인으로 옮기지 않는다.
- [Ridge 공식 구현 설명](https://scikit-learn.org/stable/modules/linear_model.html#ridge-regression-and-classification):
  L2 계수 축소와 sparse selection의 차이를 확인했다. 기본 CV 설정은 금융 월별 분할로 대체한다.

## 작업 순서와 완료 기준

1. **세대 분리:** 로컬 원본 스냅샷·Gold 메타데이터 보존·빈 새 라이브러리·혼입 차단.
2. **데이터 계약 확정:** 기존 복구 이슈와 새 입력 표를 대조하고 사용 가능한 기간을 확인.
3. **레퍼런스 재구현:** 문헌 원형/변형 구분, 신호·팩터 수익률 별도, 입력/SQL/시점 검증.
4. **새 단일 팩터 연구 연결:** 레퍼런스 버전·비교 실험을 동결해 기존 진단/독립 교훈 절차 연결.
5. **압축·선택 비교:** 같은 개발 자료와 예산으로 비교, 미래값 변조 테스트, 모든 시행 기록.
6. **전략 실행:** 월초 체결 label·비용·제약·시장 TR 준비 후 실제 backtest.
7. **최종 검증·발행:** 공동 동결한 파이프라인을 별도 검증 후 새 Gold namespace에만 게시.

합성 데이터 실행은 위 절차의 소프트웨어 검증이며 새 팩터 승인·한국 시장 성과·운영 배포가 아니다.
