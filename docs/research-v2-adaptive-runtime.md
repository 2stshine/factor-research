# 연구 v2 적응형 진단 실행기

아래는 최초 개발 실행기 설명이다. 경제적 주장 계약과 간결한 기준선을 연결한 새 버전의
24건 실험은 [최신 비교 보고서](research-v2-comparison-20261001.md)와
[버전별 명령](../scripts/research_comparison.py)에 기록했다. 기존 실행기의 코드와 점수는 보존했다.

2026-10-01. 다음에 무엇을 검사할지 에이전트가 선택하고, 근거와 한계를 남기는 최소 실행기를 구현했다.
현재 실행 범위는 **합성 데이터 개발 실험**이다. 실제 팩터 승인·봉인 OOS·Gold·기존 연구 지침을 변경하는 경로가 아니다.
전체 설계의 권한 격리·실데이터 연결·기억 학습까지 구현됐다는 의미도 아니다.

후속 [실제 실행 결과](research-v2-progress-20261001.md)에 9개 LLM 사례, 비교 결과의 채점 한계,
DART 연결 시험과 레짐 갱신을 구분해 기록했다.

## 연구자의 역할

에이전트는 경쟁 설명을 만들고, 각 설명에서 예상되는 관측을 적고, 다음 진단과 중단을 선택한다.
모든 분석을 끝낼 의무는 없다. 다만 하지 않은 검사는 미확인으로 남겨야 한다.
새 진단 설계도 제안할 수 있으나 현재 실행기에 등록되지 않은 코드는 곧바로 실행하지 않는다.

최초 버전은 등록된 여섯 진단에서 선택하는 제한된 자율성이다. 자유로운 새 검사의 생성·샌드박스 실행과
통계적 적합성 검토는 후속 단계다. 고정 목록 선택을 완전한 자율 과학자로 설명하지 않는다.

| 에이전트가 결정 | 고정 실행기가 지킬 것 |
|---|---|
| 어떤 설명을 구분할 것인가 | 원래 신호·기간·대상·비용을 바꾸지 않음 |
| 다음에 어떤 진단을 할 것인가 | 등록된 진단·예산·허용 scope만 실행 |
| 자료가 더 필요한가 | 요청을 기록할 뿐 임의 수집·네트워크 실행 안 함 |
| 새 검사가 필요한가 | 제안은 미실행 검토 대상으로 보관 |
| 언제 멈출 것인가 | 근거 없는 통과나 인과적 증명을 허용하지 않음 |

진단 선택은 결과를 보고 바뀔 수 있다. 팩터 자체의 정의를 바꾸는 것은 별도의 새 후보이며,
이 실행기는 기존 후보 등록과 최종 검증 규칙을 대신하지 않는다.

## 구현과 재개

- [실행기](../engine/adaptive_research.py): 계약, 공개 입력, 예산 예약, 등록 진단 호출, 결과와 종료 기록.
- [합성 실험실](../engine/research_diagnostic_lab.py): 96개월·120자산의 생성 패널과 실제 수치 진단.
- [기준 정책과 채점기](../engine/adaptive_diagnostic_policies.py): 고정 순서·규칙 기반 적응형과 별도 정답 비교.
- [명령](../scripts/research_diagnostics.py): 초기화, 기준 비교, 공개 packet, 행동 제출, 사후 채점.
- [실험 계획](../research/v2/adaptive-plan.json): 예산, 비교 조건, 지표와 다음 단계 조건.

각 세션은 별도 SQLite 원장이다. 계약·정확한 공개 프롬프트·행동·거절·검사 결과를 순서대로 기록하고
내용 해시로 연결한다. 실행 전 예산 예약을 commit하며, 같은 요청의 재시도는 같은 결과를 반환한다.
같은 요청 ID의 다른 내용, 오래된 revision, 관측하지 않은 근거, 중복 검사, 예산 초과를 거부한다.
실행 도중 종료되어 완료 여부를 모르면 자동 재실행하지 않고 `PENDING_RECONCILIATION`으로 둔다.
실패한 검사도 사용 예산에서 지우지 않는다.

호스트 LLM에는 합성 실험실 객체나 정답이 아니라 새로 직렬화한 공개 JSON만 전달한다.
정답은 사후 채점기만 사용한다. 외부 모델 서비스·API 키·추가 과금 코드는 내장하지 않았다.
`complete(packet)` 호스트 callback 또는 `packet`과 `act` 명령으로 실제 에이전트를 연결한다.

공유 파일시스템이므로 격리는 `LOGICAL_ONLY`다. 프롬프트의 열람 제한을 OS 수준의 접근 차단이나
강한 미열람 인증으로 주장하지 않는다. SQLite 해시 이력도 파일 소유자에 대해 변조 불가능한 장치는 아니다.
실데이터와 봉인 결과를 연결하려면 별도 데이터 중개·권한 격리가 필요하다.

## 공개 행동 계약

공통 필드는 `kind`, `reason`, `evidence_ids`, `payload`다. 공개 packet에 허용 값과 자료형을 같이 전달한다.
`reason`과 `limitations`는 문자열이며 목록이 아니다. `evidence_ids`와 `findings`는 문자열 목록이다.

| 행동 | 내용 | 효과 |
|---|---|---|
| TEST | 진단 ID, 경쟁 설명 2개 이상, 각 예상 관측, 해석을 바꿀 조건 | 예산을 예약한 뒤 신뢰된 진단 실행 |
| STOP | 관측 근거, 진단 결론, 발견 항목, 한계 | 해당 에피소드 종료; 팩터 승인 아님 |
| REQUEST_DATA | 필요한 데이터, 구분할 설명, 기대 효용 | 미확보 요청으로 기록하고 종료 |
| PROPOSE_TEST | 질문, 검사 설계, 구분할 설명 | 미실행 검토 제안으로 기록하고 종료 |

`STOP`은 입력 무효, 노출 관련 설명, 비용 소멸, 조건부 관계, 관계 잔존, 불확실, 자료 필요, 복합으로 구분한다.
경제적 인과 메커니즘이 증명됐다는 필드는 허용하지 않는다. 결론 코드의 존재나 형식 검증만으로
그 해석의 실증적 진실을 보증하지 않으며 별도 채점과 검토가 필요하다.

## 비교 실험의 범위

아홉 생성 유형은 정상 효과, 미래정보 혼입, 업종 혼입, 규모·유동성 혼입, 비용 소멸, 레짐 차이,
복합 설명, 약한 관계, 경제 결과 자료 부족이다. 진단은 미리 만들어 둔 답변을 반환하는 것이 아니라
실제 생성 패널에서 가용 시점·상관·같은 표본 통제·고정 보유 비용·레짐 간 직접 차이를 계산한다.

각 조건은 동일한 공개 자료, 진단 catalog, 10 진단 비용 단위와 10 행동 상한을 사용한다.
고정 정책에도 미래정보 혼입 발견 후 즉시 종료를 허용한다. 불필요한 검사를 강제해 약한 비교 대상을 만들지 않는다.
실제 LLM은 사례마다 새 컨텍스트에서 진단을 선택한다. 규칙 기반 적응형은 LLM 성과가 아니다.

처음 두 실행은 종료 용어 목록과 필드 자료형이 충분히 공개되지 않은 인터페이스 결함을 발견했다.
원본을 보존하고 공개 enum·자료형·구체적 형식 오류를 추가한 새 실행으로 수정했다.
이는 개발용 smoke 시험이며 인터페이스 수정 후 같은 생성 유형을 다시 사용한 것을 독립 최종 평가로 부르지 않는다.

주 결론 정합성, 잘못된 발견 코드, 정상 효과 보존, 적절한 판단 보류, 추가 자료 요청, 비용을 각각 보고한다.
생성 과정의 정답과 유한 표본에서 정당화되는 해석은 완전히 같지 않으므로 자동 채점의 불일치는 별도 검토한다.
서로 다른 seed는 새로운 시장·새 가설의 독립 재현이 아니다.
토큰·금전 비용은 호스트 영수증 없이는 미측정이며 0으로 쓰지 않는다.
진단 비용 단위만으로 전체 LLM 비용이 절감됐다고 주장하지 않는다.

월별 HAC 구간은 탐색적 불확실성 표시다. 같은 패널을 적응적으로 다시 분석한 p값이나 구간을 합쳐
POPPER의 순차 오류 통제가 성립한다고 주장하지 않는다.
[POPPER 원문](https://proceedings.mlr.press/v267/huang25n.html)의 실험 설계·실행 분리를 참고하되
조건부 증거 유효성은 금융 패널에서 별도로 입증해야 한다.

## 실행 예

기존 실행 디렉터리는 덮어쓰지 않는다. 원본 코드와 계획도 실행 artifact에 동결한다.

```sh
.venv/bin/python -m scripts.research_diagnostics init --run output/my-new-diagnostic-run
.venv/bin/python -m scripts.research_diagnostics references --run output/my-new-diagnostic-run
.venv/bin/python -m scripts.research_diagnostics packet --run output/my-new-diagnostic-run --case CASE_ID
.venv/bin/python -m scripts.research_diagnostics act --run output/my-new-diagnostic-run --case CASE_ID \
  --action my-action.json --request-id host-1 --revision REVISION
.venv/bin/python -m scripts.research_diagnostics score --run output/my-new-diagnostic-run --output output/my-score.json
```

`references`는 규칙 기반 기준선만 실행한다. `packet`은 실제 LLM 실행 완료가 아니다.
호스트가 각 packet에 행동을 제출해야 실제 LLM 에피소드가 된다.
`score`는 정답을 사용하는 평가자 전용이며 사례를 푸는 에이전트에게 결과를 전달하지 않는다.

## 이후 단계

실행 경계 검사와 실제 LLM의 유효한 종료를 확인하고, 오류·과장된 결론을 검토한 다음 작은 실데이터 파일럿으로 진행한다.
작은 합성 시험만으로 적응형의 일반적 우월성을 확정하지 않는다. 실데이터 파일럿은 별도 입력 계약,
자격과 노출 기록, 자료별 가용시각, 주장별 커버리지 확인을 요구한다.
최종 검증·승격·실전 사용은 기존 계약을 통과해야 하며 자동 연쇄 실행하지 않는다.

기억은 초기에는 새 근거와 해석 이력을 저장하는 최소 구조로 둔다. 검토되지 않은 합성 결과를
실제 한국 주식의 교훈으로 넣거나 기존 기억에 자동 병합하지 않는다.
그래프 검색·기억 효용 학습·대시보드 전면 전환은 실제 연구 흐름이 검증된 이후에 진행한다.
