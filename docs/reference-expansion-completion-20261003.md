## 데이터 품질과 PIT

- 가격 원자료는 사전에 고정한 10개 종목의 21,698개 일별 행을 독립 집계해 1,065개 월별 행·31개 필드와 대조했다.
  이것은 원자료 표본 감사다. 모든 원천 가격·모든 공시를 외부 제공자와 독립 전수 대조했다는 뜻은 아니다.
- 신규 38개는 각각 최소 100종목·전체 관측 월 60개라는 사전 데이터 기준을 통과했다.
  모든 종목이 60개월 이력을 갖거나 수익성이 좋다는 기준이 아니다.
- 재무는 당시 가용한 최신 FY 공시를 선택하고, 전년은 정확한 전년 결산기·동일 CFS/OFS 범위로 대응했다.
  현 시점 수정값을 과거 월에 일괄 소급하지 않는다. 최신 FY가 550일보다 오래됐으면 사용하지 않는다.
- KRW만 사용하고 암묵적 환산을 하지 않았다. 충돌 계정·부적합 범위·결측을 과거 공시나 0으로 채우지 않는다.
- 완전한 자산·부채·자본 묶음의 차이가 `max(1원, abs(자산)×10⁻⁶)`를 초과한 9개 공시/회계범위 사례는 격리했다.
  월별 연결상 현재 FY 85개, 전년 FY 61개 종목-월에 해당한다. 반올림 가능성을 포함하므로 원천 오류 확정이라고 부르지 않는다.
  격리 후 완전한 현재 FY 259,595개·전년 FY 215,827개 종목-월에서 등식 위반 0개를 확인했다.

1. 신규 38개를 최대 3개씩 13개 묶음으로 발행했다. 기존 7개 데이터셋은 덮어쓰지 않았다.

## 연구에서 읽는 방법

[계약·CLI 안내](reference-library-phenomena.md)를 따른다. DB 연결은 기존 환경·인증을 사용하며 비밀키를 코드에 넣지 않는다.

```python
from pathlib import Path
from engine.reference_db import connect
from engine.phenomenon_references import load_active_references, reference_fields

root = Path.cwd()  # factor-research 저장소 루트
selected = ["kr_turnover_1m_v1", "kr_roa_fy_v1"]
cache = root / "output/phenomena/reference-expansion-20261003/build-v2/collection-cache"

with connect() as conn:
    values, metadata = load_active_references(
        conn, root, reference_ids=selected, snapshot_path=cache
    )
features = reference_fields(values, metadata, selected)
```

캐시는 전송량을 줄일 뿐 DB 조회를 우회하지 않는다. 선택한 지표가 속한 데이터셋 전체를 검증한다.
목적에 맞는 ID를 명시적으로 선택하고, 반환된 개별 known-at·결측·정의 해시·원천 버전을 함께 사용한다.
collection ID는 Gold 단일 dataset ID가 아니므로 SQL의 dataset 키로 대신 넣지 않는다.

최종 실행 증빙은 `output/phenomena/reference-expansion-20261003/build-v2/`에 있다.
초기 `price-source`·`financial-source`의 중단 기록과 교체된 `build`는 감사용으로 보존하며 완료 입력으로 재사용하지 않는다.
현재 원천은 `price-source-v2`, `financial-source-v2`다. 완료 원천을 다른 build에 재연결할 수 있고,
완료 checkpoint도 실제 DB를 재조회한 후에만 재사용한다.
