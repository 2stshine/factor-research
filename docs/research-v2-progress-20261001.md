후속 업데이트: 아래는 최초 9건 개발 시험과 실데이터 입력 준비 기록이다.

성과에 맞게 바꾸는 기능까지 허용한 것은 아니다.

## 실제 LLM 비교 결과

동일한 9개 합성 사례, 동일한 진단 목록, 사례별 10 진단 비용 단위·10 행동 상한을 사용했다.
고정 방식에도 미래정보 혼입을 발견하면 즉시 종료할 수 있게 했다.

| 비교 조건 | 유효한 종료 | 생성 시나리오와 주 결론 일치 | 진단 비용 합계 | 원래 채점기의 발견 코드 불일치 |
|---|---:|---:|---:|---:|
| 고정 검사 순서 | 9/9 | 8/9 | 73 | 1 |
| 규칙 기반 적응형 | 9/9 | 7/9 | 64 | 0 |
| 실제 LLM의 검사 선택 | 9/9 | 9/9 | 72 | 4 |

실제 LLM은 미래정보 혼입 사례에서는 입력 검사 후 멈췄고, 비용 소멸 사례에서는 비용을
확인한 뒤 멈췄다. 국면에 따라 부호가 바뀌는 사례에서는 두 국면의 기울기 차이를 직접
검사했다. 정상 효과 2건은 유지했고, 약한 효과 1건에는 판단을 유보했다.
허용되지 않은 행동이나 예산 초과는 없었다.

이 결과로 LLM이 더 우수하거나 더 저렴하다고 결론 내리지는 않는다. 인터페이스를 수정하며
같은 개발 사례를 재사용했고, 사례 수가 작으며, 토큰·금전 비용도 측정하지 않았다.
72 대 73은 진단 비용 단위 비교일 뿐 전체 운영비 절감 근거가 아니다.
규칙 기반 두 방식만 추가 seed를 포함해 각각 81회 실행했으며 이는 실제 LLM 81회가 아니다.

이번 공개 질문의 주 평가 대상은 입력·통제·비용을 거친 예측 관계였다. 경제 outcome 검사는
선택 사항이었고 실제 LLM 9건 모두 실행하지 않았다. 자료 요청도 0건이다. 따라서 이 시험은
**데이터 확보 우선순위 판단이나 새로운 검사 발명 능력까지 검증한 결과가 아니다.**
이를 평가하려면 경제 설명의 구분이 주 질문인 별도 동결 사례와 예산을 마련해야 한다.

비교 기준도 더 강화해야 한다. 통제 진단이 원래 상관관계까지 함께 반환하므로, 실제 LLM은
9건 모두 별도 단순 상관 검사를 생략했다. 고정 방식은 이 검사를 먼저 수행했다.
따라서 관측된 차이는 **검사 중복 제거·순서 개선의 효과와 LLM 판단의 효과가 분리되지 않은 결과**다.
다음 동결 비교에는 입력 검사 → 통제 → 비용 → 국면 차이의 간결한 고정 기준도 포함해야 한다.
현재 결과를 보고 추가한 이 제안을 원래 사전등록 기준으로 소급 표시하지 않는다.

### 채점기가 틀리게 구분한 부분도 남겼다

LLM의 발견 코드 불일치 4건은 모두 `MECHANISM_UNIDENTIFIED`였다.
에이전트는 “인과 메커니즘은 확인하지 못했다”고 적었지만, 채점기는 이 코드를
“경제 outcome 데이터가 실제로 없는 사례”로만 해석했다. 별도 코드·응답 검토에서도 이 4건의 문장은
인과관계를 과장한 것이 아니라 검사하지 않은 범위를 명시한 것으로 확인했다.

반대로 데이터 부족 사례에서 같은 코드가 일치했더라도 실제 경제 outcome 검사를 하지
않았다면 데이터 부족을 찾아낸 성과로 인정하면 안 된다.
[후속 주장 계약](../engine/research_diagnostic_claims.py)을 별도 모듈로 추가해 **미검사 / 검사했으나
자료 없음 / 연관성 계산 / 미해결**을 분리하고, 인과관계는 모두 미확인으로 둔다.
자료 부족 발견에는 그 결과의 정확한 근거 ID 인용을 요구한다. 이 계약은 현재 v3 실행기에
자동 연결하지 않았으며, 기존 점수를 소급 수정하지 않는다.

고정 방식의 불일치 1건도 주의해서 읽어야 한다. 국면을 합치면 관계가 약한 사례에서
판단을 유보했고, 예산 안에서 국면 검사에 도달하지 못했다. 생성 원인은 놓쳤지만,
검사한 자료에 대한 판단 유보 자체를 거짓 인과 주장으로 취급하지 않는다.

원래 점수와 실패한 v1/v2 실행은 보존했다. 사후에 정답 점수로 바꿔 쓰지 않았다.
[검토 기록](../research/v2/adaptive-review-20261001.json)과
[원래 v3 결과](../output/research_v2_adaptive/run-20261001-v3/final-score.json)를 함께 읽는다.

## 실데이터 연결에서 확인한 것

[DART 연결 함수](../engine/research_statement_evidence.py)는 기준시각까지 가용한 최신 FY 공시를
고르고, 그 공시 내 CFS를 우선하며, CFO와 자산의 기간·통화·계보를 맞춘다.
최신 공시가 불완전하다고 이전 공시의 값을 몰래 되살리지 않는다.
비어 있는 기업도 분모에 남기며 연결 실패 이유를 반환한다.

실제 RDS를 읽기 전용으로 조회해 지정한 3기업의 149개 정규화 행을 받았다.
FY2024 자료를 2025-06-30 23:59:59 KST 기준으로 연결한 결과는 **3/3**, 모두 CFS·KRW였다.
저장된 행으로 재계산한 결과와 해시도 일치했다.

이것은 **연결 시험**이다. 시장 전체 coverage, 최초 발표본 보유, 단위 인증, 미래 실적과의 관계,
실제 정정 다중 빈티지 선택을 모두 확인했다는 뜻은 아니다. 이 표본은 기업별 공시가 한 개여서
정정·모호성 거부 동작은 합성 테스트로만 검사했다. 매핑되지 않은 최신 공시는 원천 뷰에서
보이지 않는 한계도 남겼다.

원천 뷰의 인증 필터를 독립적으로 확인하지 않고 단정한 v1 설명은 보완했다.
새 v2 산출물에는 정확한 뷰 정의·질의·실행 코드와 해시를 보존하고 인증 조건은
“기대하는 원천 계약이며 이 조회에서 독립 검증하지 않음”으로 표시한다.
v1 결과는 삭제하지 않았다.

### 별도 가격 패널 갱신과 조회 비교

기존 활성 캐시의 총수익 인증 계보가 현재 RDS와 달라 identity 검사가 실패했다.
이를 무시하거나 기존 캐시를 덮어쓰지 않고 `.cache/research-v2-20261001`에서 원래 빌드
명령으로 별도 재계산했다. 가격 736,679개 자산·월과 재무 94,282개 스냅샷·3,076종목을
연결한 캐시를 만들었다. 현재 완료 상태와 재대조 결과는 [단계별 상태](../research/v2/adaptive-state.json)의
`panel_refresh`에 기록한다. 가격 행에는 과거 비활성 종목과 오래된 입력 이력이 포함된다.
최신 유니버스는 2,493종목이며, 모든 기간에서 그 종목 수를 썼다는 뜻은 아니다.
입력 재계산을 새 팩터 평가로 세지 않는다.

최종 [RDS 재대조](../output/research_v2_preflight/panel-identity-audit-20261001.json)는 **MATCH**다.
2026-09-30까지의 자산·월·종목코드 identity가 같은 736,679행·6,692개 역사적 자산·377개월이고,
현재 총수익 인증 계보도 검사했다. 이는 현재 입력 계약의 일치 확인이지 최초 발표 빈티지의
독립 재인증이나 팩터 유효성 검증은 아니다. 새 캐시는 기본 `.cache/panel.pkl`로 활성화하지 않았다.

긴 조회를 검토하며 종목코드 집계를 일별 계산 뒤의 월말 행에서만 수행하는 선택 경로도
분리했다. 실제 3개 자산 **951행**에서 원본·변환 쿼리의 모든 열과 값이 일치했다.
첫 비교는 13.37초/1.88초였지만 재실행은 2.56초/2.57초였으므로, 캐시와 실행 순서의 영향이
섞여 **속도 개선은 입증되지 않았다**. 원래 실행 중인 빌드를 취소·교체하지 않았다.

## 레짐과 3년 룩백

기존 Bronze에서 KOSPI/KOSDAQ 원본 100개를 로컬에 추가했다. 최신 거래일은
**2026-09-30**이다. 제공사 API를 다시 호출하거나 기존 파일을 덮어쓰지 않았다.
새 shadow는 시장별 141개월 중 126개월이 판독 가능하고 초기 15개월이 UNKNOWN이다.

지표는 10개월 추세, 일별 수익률의 63일 위험, 21일 대 63일 위험 변화, 직전 12개월 대비
상대 위험으로 구성한다. 판독 이름만 남기지 않고 연속 위험값을 함께 보존한다.
기존 연구의 레짐·판정은 변경하지 않았다. [별도 레짐 갱신 보고서](research-v2-regime-refresh.md)에
9월 완료 계약, 과거 값 불변성, 달력 한계를 기록했다.

사용자가 지적한 3년은 **입력 룩백**이다. OOS 36개월을 줄이지 않았다.
새 계획기는 신호의 실제 룩백·원천 계산 이력·미래 outcome 기간을 구분한다.
기존 전역 36개월 상한이나 평가 시작월을 조용히 바꾼 것은 아니다.
실제 새 후보의 짧은 룩백 적용은 파일럿 계약에서 검증해야 한다.

## 남은 실행 순서

1. 후속 주장 계약을 새 실행기에 연결하고 실데이터 진단에 필요한 기간·열·반환 경계를 구현한다.
2. 갱신 패널의 인증 계보·자산 identity를 확인한 뒤 가설별 증거 카드를 작성한다.
3. 해당 후보의 실제 전체 분모로 입력·통제·경제 outcome의 coverage를 검사한다.
   메커니즘 자료가 없다는 이유만으로 별도의 가격 예측 연구까지 막지는 않는다.
4. 결과를 보지 않고 적격 후보와 비교 기간·비용·룩백을 동결해 소규모 파일럿을 등록한다.
5. 파일럿 관찰을 검토한 뒤 동결 검증으로 진행한다. 재사용된 과거 OOS를 새 미노출 자료로
   취급하지 않는다.
6. 검토된 실제 교훈만 새 기억과 대시보드에 반영한다. 합성 시나리오의 정답은 한국 주식의
   경제적 교훈으로 넣지 않는다.

팩터 승인·Gold 적재·실전 국면 교체·웹사이트 배포·커밋/병합은 이 작업의 실행 완료 목록에
포함하지 않는다. 기존 연구·노출 원장과 사용자가 수용한 매크로 PIT 가정은 보존했다.

## 검증과 재개

관련 단위·회귀 테스트 **328개가 통과**했다. 코드 테스트는 시장에서 팩터가 작동한다는
검정이 아니다. 합성 실행의 정확한 입력·행동·결과는 SQLite 원장에 남아 있으며 중단 후
같은 요청을 재전송해도 중복 실행하지 않는다. 실제 데이터·검증 자료의 OS 수준 격리는
아직 제공하지 않으므로 `LOGICAL_ONLY`를 유지한다.
