## 2. 동일 원장으로 측정한 실제 영향

2015-01~2023-06의 **230,671개 자산-월**을 비교했다. 가격·유니버스는 고정하고,
정확한 이전 코드와 수정 코드를 **같은 인증 원장**에 적용했다. 다음 숫자는 수익률이 아니다.

| 입력 | 값→결측으로 바뀐 자산-월 | 영향받은 자산 |
|---|---:|---:|
| 매출 TTM | 11,616 | 1,226 |
| 영업이익 TTM | 11,719 | 1,244 |
| 세전이익 TTM | 11,777 | 1,243 |
| 순이익 TTM | 11,830 | 1,252 |

각 행의 자산·월은 중복되므로 합산해 고유 자산 수라고 하지 않는다. 위 네 TTM의 유효 숫자끼리
수치가 바뀌거나 결측에서 값으로 늘어난 경우는 없었다. 9개 재무상태표 입력은 바뀌지 않았다.
단독 분기값, 순이익 전년동기 변화 및 SUE에도 파생 영향이 있다. 독립 SQL 검증 범위는
FLOW 단독 분기/TTM이며 **SUE와 모든 팩터의 승인 성능까지 재검증한 것이 아니다**.
기존 Gold를 자동 교체하지 않은 이유이기도 하다.

순이익 YoY와 SUE는 동일 분기 배열을 공유한다. 새 결측 장벽이 위치 기반 4분기 비교와
최근 변화량 표본에 영향을 줬으며, 각각 2,120/1,336개 월행이 결측에서 값으로 바뀌었다.
전체 변경은 각각 2,336/4,561행이며, 이 중 유효값끼리의 변경도 각각 210/3,191행이다.
이는 자료 보강이나 별도로 입증한 품질 개선을 뜻하지 않는다. 각 변경의 원인 비중 및
전체 TTM 탈락 원인의 비중까지 개별 계보로 분류한 감사는 아직 하지 않았다.

매출 성장가속도 후보의 수식·부호·월별 리밸런싱과 검사 경계는 그대로 유지했다.

이 coverage의 분모는 **2018-03~2023-06, 64개월의 원래 연구 유니버스 135,314자산-월**이고,
수정 후 유효 신호는 76,212개다. 앞의 TTM 감사 범위 230,671행과 분모가 다르다.

작은 차이가 있어, 이전 보존 결과와의 차이를 전부 코드 수정 효과라고 해석하지 않는다.
원천 버전 변화의 세부 원인은 이 비교만으로 확정하지 않는다.

2018-03~2019-01의 11개월에는 신호가 여전히 하나도 없다. 2015·2016년 월별 패널의
매출 TTM도 전부 결측이다. 수정 코드는 과거 자료를 만들어내지 않는다. 등록·수익률 계산·
적응형 교훈 진단으로 진행하지 않았으며, 입력 부족을 경제적 가설의 실패로 기록하지 않았다.

## 3. 2015년 자료는 어디까지 복구했나

보유 Bronze/Silver의 초기 분기 공백을 확인하고, 삼성전자·SK하이닉스·현대차의
2015 Q1/Q2/Q3 **원문 공시 ZIP 9건**을 확보했다. 원문·응답 metadata·SHA를 보존했다.
수집 호출은 실패·재시도 포함 총 20회, 응답 2,566,190바이트였다.

별도 staging 추출기는 본문 재무제표의 연결/별도 구분, 표 머리글, 단위, 당기 기간,
3개월/누적 열을 검증해 **18개 재무표의 매출 값셀 36개**를 추출했다. 36개의 독립 분기
표본이 아니다. Q1의 3개월·누적 값은 같은 기간이며 연결/별도도 분리된 재무 범위다.

- ZIP→XML→표 hash→물리적 행→셀·헤더→원시 금액·원화 단위의 근거를 연결했다.
- UTF-8 선언과 실제 CP949 바이트의 불일치를 명시적으로 처리했다.
- 3사×연결/별도×Q2/Q3의 12개 비교에서 누적 차이와 당기 3개월 매출이 일치했다.
- 단순 추출 성공은 최초 공시·전체 정정 이력 검증이 아니다. 모든 결과를
  `STAGED_PIT_UNVERIFIED`, `financial_available_at=null`, `input_connected=false`로 보존했다.
- 이번에는 S3/RDS/Gold 게시 또는 후보 입력 연결을 하지 않았다. 로컬 원문·staging만 추가했다.

2015년 전체 API 미지원을 단정하지 않는다. 기존 major 수집기는 모든 연도에 분기 코드를
요청한다. 공식 bulk 목록은 2015 FY부터, 분기는 2016 Q1부터 보였고, 실제 삼성전자 2015 Q1
주요계정 API 표본은 `013`이었다. 이것은 전 기업·다른 endpoint까지 부재라는 증거가 아니다.
[OpenDART 주요계정 가이드](https://opendart.fss.or.kr/guide/detail.do?apiGrpCd=DS003&apiId=2019016),
[공식 재무정보 일괄다운로드](https://opendart.fss.or.kr/disclosureinfo/fnltt/dwld/list.do).
