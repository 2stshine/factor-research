# 연구 v2: 네 논문에서 가져오는 것과 가져오지 않는 것

작성일: 2026-10-01 · 논문 읽기·설계 근거 기록

[전체 설계](research-v2-design.md) · [구현 계약](research-v2-contracts.md)

## 1. 해석 원칙

네 논문은 같은 문제를 해결하지 않는다. 연구의 진행 구조, 기억의 생성, 기억의 검증, 기억의 검색 효용을 각각 다룬다. 따라서 하나의 순위표에서 최고 성능 논문을 고르기보다 담당 기능을 나눠 채택한다.

| 논문 | 우리 설계에서 맡길 일 | 맡기지 않을 일 |
| --- | --- | --- |
| Praxist | 실험→근거→다음 질문의 연구 운영 | 최고 백테스트 점수로 팩터 승인 |
| ReasoningBank | 실행 경험에서 범위 있는 교훈 작성·검색 | 자기평가만으로 교훈의 진실성 확정 |
| Grounding Agent Memory | 교훈의 확인·수정·적용 조건 관리 | 현재 환경 확인으로 미래 알파 지속성 입증 |
| MemRL | 관련성 외에 실제 수행 효용을 측정 | IC·수익률로 기억을 직접 강화 |

아래 “논문 내용”은 원문 요약이고 “반영 결정”은 우리 환경을 위한 제안이다. 네 구성요소의 결합 성능, cold start의 우월성, 특정 국면·기간·검색 개수는 논문들이 보증하지 않는다. 논문 벤치마크 수치를 한국 주식 연구의 예상 성과로 옮기지 않는다.

## 2. Praxist

원문: [Praxist v1](https://arxiv.org/html/2608.25955v1), 2026-08. 확인 범위: 본문, 관련 알고리즘·평가, Appendix A의 상태·계획·PI·Chair·Gems·프롬프트와 사례/한계. 공식 문서·일부 실제 프롬프트도 대조했다.

**논문 내용:** 실행 산출물, 해석된 finding, 현재 유망/미해결 연구 목록, 다음 agenda, 계보를 구분한다. 선택 기능인 여러 PI와 Chair는 서로 다른 관점의 검토를 제공한다. 대표 기본 설정에서 multi-PI와 Gems가 모두 항상 켜지는 것은 아니다. 금융 사례의 사후 최고 수익 결과도 검증 gate를 통과한 단일팩터 알파의 증거가 아니다. 전체 시스템 사례만으로 각 구성요소의 독립 효과를 확정할 수 없다.

**반영 결정:** 연구 프로그램과 단일 실험 계약을 분리하고, 긍정·음성·불확실한 결과를 모두 보존한다. 다음 연구는 최고 IC가 아니라 해결할 질문으로 선택한다. 계획 계약을 모든 trial에 요구하며 실패 시 자유 탐색으로 조용히 대체하지 않는다. Chair는 판정·OOS 권한을 바꾸지 못한다. 메커니즘 결합을 권하는 기본 프롬프트는 단일팩터 연구에 그대로 사용하지 않는다.

공식 구현의 graph는 원결과를 바꾸는 권위가 아니라 보조 뷰다. 우리 설계의 append-only 해석 버전, 내용 해시, 독립 근거 단위와 전역 노출 원장은 별도 보강이다. [공식 architecture](https://github.com/sapientinc/PRAXIST/blob/main/docs/concepts/architecture.md), [Chair prompt](https://github.com/sapientinc/PRAXIST/blob/main/praxist/plugins/workflow_stages/research_loop/backend/multi_pi/prompts/chair.jinja2). 이 링크의 `main`과 논문 v1이 동일한 커밋이라는 보장은 하지 않는다.

## 3. ReasoningBank

원문: [ReasoningBank v2](https://arxiv.org/html/2509.25140v2), 최초 2025-09. 확인 범위: 본문, 방법·실험·한계, Appendix A–F의 환경·비용·사례·프롬프트·ablation. 공식 구현 일부도 대조했다.

**논문 내용:** 빈 기억에서 출발해 성공과 실패 경험을 재사용 가능한 교훈으로 만들고 다음 과제에 검색한다. 기본 설정은 관련 경험 하나에 연결된 교훈들을 전달하며, 단순히 기억을 많이 넣는 것이 항상 좋은 것은 아니다. 자기평가에 의존하는 오류 가능성이 있고, 원래 append-only 방식은 오래되거나 틀린 교훈의 수정을 충분히 해결하지 않는다. MaTTS의 여러 시도 비교는 추가 계산을 사용한다.

**반영 결정:** 결과 기록과 재사용 지침을 분리하고 짧은 소수의 교훈을 출처·조건과 함께 저장한다. 교훈이 없으면 0개로 종료한다. 교훈 생성자의 자기평가만으로 활성화하지 않고 별도 검토·정정 절차를 둔다. 여러 구현/검토의 비교는 합성 fixture·코드 품질·근거 해석에 사용한다. 여러 팩터를 무등록 실행해 최고 IC를 고르는 용도로 사용하지 않는다.

공식 구현 참조: [memory management](https://github.com/google-research/reasoning-bank/blob/ed80611788292ea739f1effd31f16c53823b8a0d/WebArena/memory_management.py), [memory induction](https://github.com/google-research/reasoning-bank/blob/ed80611788292ea739f1effd31f16c53823b8a0d/WebArena/induce_memory.py). 코드 대조는 논문 실험 재현을 의미하지 않는다.

## 4. Grounding Agent Memory

원문: [Grounding Agent Memory v1](https://arxiv.org/html/2609.11060v1), 2026-09. 확인 범위: 본문, Appendix A–D의 runtime·평가·지표·프롬프트, 관련 memory/probe 사례. 전체 실험 archive를 재현하지 않았다.

**논문 내용:** 작업 에이전트는 기억을 읽고, 별도 curator가 종료된 실행에서 교훈을 검토·수정한다. 읽기 전용 환경 확인으로 잘못된 가정과 변경된 조건을 검토한다. 성공한 작업의 중간 가정이 전부 맞았다는 보장은 없다. 보고된 전체 memory 효과와 probe의 추가 효과를 구분해야 하며, headline 작업 비용에는 별도 정리 비용이 포함되지 않는 범위가 있다.

**반영 결정:** 연구자와 기억 writer를 분리하고 새 세션의 curator에 허용된 자료만 제공한다. probe를 읽기 전용이라는 이유만으로 허용하지 않고 데이터 scope·시점·작업 종류를 제한한다. 시간·호출 상한은 우리 운영 제안이며, 상한 내 확인하지 못하면 미확인으로 남긴다. 전체 비용에 distiller·검토·probe·색인을 포함한다. 경제적 효과의 지속성을 스키마 확인과 같은 방식으로 검증했다고 주장하지 않는다.

대응하는 공식 실험 구현 저장소는 이번 검토에서 확인하지 못했다. 논문이 사용하는 SDK를 논문의 전체 실험 코드로 간주하지 않는다.

## 5. MemRL

원문: [MemRL v2](https://arxiv.org/html/2601.03192v2), 최초 2026-01. 확인 범위: 본문·알고리즘·실험, 관련 Appendix B–G·I의 설정·ablation·한계·프롬프트. 수학적 가정과 증명의 적용 범위를 검토했으나 증명을 독립적으로 재검증하거나 실험을 재현하지 않았다.

**논문 내용:** 고정된 언어모델이 외부 기억을 검색할 때 의미 관련성과 경험에서 추정한 효용을 결합한다. 사용된 기억에 최종 보상을 업데이트하는 방식은 여러 기억 중 어느 것이 기여했는지 완전히 분리하지 못한다. 고정 모델·과제 분포 등의 가정을 금융 환경 변화에 그대로 적용할 수 없고, 반복 과제의 개선과 새 과제 일반화도 구분해야 한다.

**반영 결정:** 효용은 사실의 신뢰도가 아니라 특정 작업·모델·프로토콜에서의 수행 도움으로 정의한다. 초기에는 순위를 바꾸지 않는 shadow mode로 측정한다. 보상은 근거 있는 연구 수행이며, 알파 수치나 승인 개수가 아니다. 여러 기억의 공동 보상은 관측 효용으로 표시한다. 효용의 인과적 효과를 말하려면 별도 통제 비교가 필요하다. 모델·기억 revision·환경이 바뀌면 이전 효용을 자동 계승하지 않는다.

공식 구현 참조: [memory service](https://github.com/MemTensor/MemRL/blob/c1b322ca43de36ddf64c6712f89d0095bfc35ce0/memrl/service/memory_service.py). 토큰 예산은 라이브러리의 문자열 길이 근사에 의존하지 않고 실제 사용 모델의 tokenizer/사용량으로 집계한다.

## 6. 금융 연구이기 때문에 따로 추가하는 방어

기억 시스템이 좋아지면 같은 자료에서 더 효율적으로 좋은 패턴을 찾을 수도 있다. 그것이 진짜 알파를 더 잘 찾는다는 뜻은 아니다. 그래서 네 논문과 별도로 개발/검증 경계와 모든 시도의 기록을 유지한다.

- 사전등록은 결과를 본 뒤의 해석을 구분하는 도구다. 등록 자체가 부적절한 검증·반복 선택을 모두 해결하지는 않는다. [Nosek et al., The preregistration revolution](https://www.pnas.org/doi/10.1073/pnas.1708274114).
- 많은 팩터 후보를 시험한 금융 연구에서는 선택·다중검정 문제를 고려해야 한다. 특정 t값이나 보정식을 기계적으로 가져오는 대신 무엇을 몇 번 시험했는지와 독립 검증 여부를 남긴다. [Harvey, Liu & Zhu, … and the Cross-Section of Expected Returns](https://www.nber.org/papers/w20592).
- 이미 본 검증 구간을 새 이름으로 다시 잠그는 것은 새로운 정보가 아니다. 과거 재사용의 고정 검증은 유용할 수 있지만 새 독립 확인과 구별한다.
- cold start는 외부 기억의 초기 편향을 줄이기 위한 운영 선택이다. 이미 시도한 가설 수, 사람·모델이 본 지식, 검증 자료의 노출을 없애는 통계적 조작이 아니다.

## 7. 읽기에서 구현으로 넘어가기 전 확인할 것

논문은 기능 선택의 근거이고, 우리 시스템에서의 효능은 별도 검증 대상이다. 먼저 범위 있는 기억과 증거 연결을 구현하고, 확인·수정 기능을 비교한 뒤, 그래프 검색과 효용 순위를 추가한다. 충분한 이점이 없으면 단순한 구성을 유지한다.

현재의 최종 제안은 **연구 운영은 Praxist, 교훈 작성은 ReasoningBank, 교훈 검증은 Grounding, 효용 평가는 MemRL에서 가져오되, 통계적 승인·데이터 접근·발행 권한은 독립된 결정론적 계약으로 통제하는 구조**다.
